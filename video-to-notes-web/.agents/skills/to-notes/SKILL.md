# To Notes — 逐字稿转结构化笔记

把原始逐字稿整理成内容完整、结构自然、方便复习的 Markdown 笔记。优先用于一至两小时长视频等难以在单次对话中稳定处理的长内容：利用 Agent 的文件读取与编辑能力分段通读、逐章写入，并在最后检查覆盖范围。

```text
逐字稿 → 快速预读 → 动态四问 → 全量通读与大纲 → 用户确认 → 逐章输出 → 完整性验证
```

## 前置条件

用户需提供逐字稿文件、粘贴转录文本，或在当前上下文中已有逐字稿。若只有视频链接，先用可用的视频转录能力取得逐字稿，再开始本流程。

## 阶段 0：快速预读

提问前必须先了解材料，避免套用不贴合内容的固定选项。

确认三个维度：

| 维度 | 判断内容 | 用途 |
|---|---|---|
| 格式 | 有无说话人、时间戳、标题和分段 | 决定可选结构 |
| 规模 | 短（少于 5,000 字）、中（5,000–15,000 字）、长（超过 15,000 字） | 决定生成策略 |
| 组织方式 | 讲座、多人分享、讨论、访谈、主题块或时间线 | 决定推荐方案 |

有文件读取工具时，先读开头和结尾各 80–120 行，再在约三分之一和三分之二处各读 30–50 行。短文本直接完整预读。此时只判断格式、规模和结构，不提前写笔记。

## 阶段 1：动态四问

四个问题的维度固定，但问题措辞、选项和推荐项必须依据预读结果动态生成，不能照搬固定模板。若当前客户端支持结构化提问工具，优先使用；工具一次最多只能问三个问题时，分成两批；没有工具时，用简短编号列表一次问完。

### 1. 笔记结构

从实际材料中选择 2–3 个合理方案，例如：

- 原内容章节清晰：推荐保留原章节结构。
- 多位发言人轮流分享：可按分享者整理。
- 原文松散但主题明确：可按知识点重组。
- 对话或事件推进明显：可按时间线整理。

不要在没有说话人标签时提供“按发言人整理”。

### 2. 详细程度

根据内容密度给出推荐，可包含：

- 要点提炼 + 关键原话：通常约原文 15%–20%。
- 完整精译：保留完整意思，口语转书面语，通常约原文 30%–40%。
- 逐条精炼：尽量保留每条有效发言。
- 速查摘要：框架、核心概念和行动项，通常约原文 5%–10%。

这些比例是参考，不是硬性字数限制。

### 3. 生成策略

- 短内容通常推荐确认设置后一次性输出。
- 中长内容通常推荐先确认大纲，再逐章输出。
- 超长内容应说明分批的必要性，避免遗漏或截断。

### 4. 附加模块

先判断正文之外的内容是否真的有价值。“只要正文笔记”应始终是可选项，并可成为默认推荐。其他选项只在适合材料时出现，例如：

- 全文摘要：长内容或需要快速回顾时。
- 关键概念词汇表：概念密集的知识讲授。
- 方法论或踩坑清单：案例分享、实操复盘。
- 行动项：会议或项目讨论。
- 问答索引：答疑内容占比较高时。

不要为了形式完整强行添加模块，也不要把模块列表固定死。

## 阶段 2：全量通读与大纲

用户回答后，完整阅读逐字稿，不跳过内容。边读边识别：

- 原有标题、纪要分段或时间轴。
- 明确的转场语。
- 能独立成章的重要知识块。
- 问答、案例、操作演示和总结。

章节应忠实于原内容，但不机械照抄。典型 2–3 小时内容通常为 5–10 章；短内容可少于此范围。

向用户提交只到二级标题的大纲：

```markdown
## 笔记大纲

### 第 X 章：章节名（仅在原文有时间戳时填写范围）
- X.1 子标题
- X.2 子标题
- X.3 子标题（重点）
```

## 阶段 3：确认大纲

等待用户确认或修改。用户确认前不要开始写完整笔记。收到修改意见后，先修订大纲并再次对齐；不要把未确认的大纲当成最终结构。

## 阶段 4：生成笔记

按确认后的章节顺序写入同一份 Markdown 文档。短内容可一次完成；长内容每批生成 3–4 章，防止截断，并持续写入同一文件或同一回答链路。

对于一至两小时长视频逐字稿，不要尝试在一次回答里压缩完成。必须分段读取原文、先建立覆盖全文的大纲，再分批写入同一文件；每批开始前确认上一批已落盘，最终对照原文首尾与大纲逐章核验。

每章可按内容自由组织，不必机械套模板。常用元素包括：

```markdown
## 第 X 章：标题（时间范围可选）

### X.1 子主题

用自然语言提炼核心观点，并补足必要的上下文。

> 「只有当原话精炼、有辨识度或不可替代时，才引用原文。」
```

内容取舍：

- 保留概念定义、方法论、实践建议、关键论证、案例数据、精彩类比和重要对比。
- 删除口头禅、无意义重复、设备调试、无关互动和纯寒暄。
- 不要为了“简洁”删除支撑结论的细节，也不要逐句改写成流水账。
- 引用必须忠于原文；概括和串联使用自己的自然语言。
- 只有确实存在多维对比时才用表格。
- 原文无时间戳时不要虚构时间范围。

目标是像认真听完整场内容的人写出的笔记：重点突出，但保留作者的思路、例子和语气，不要生成千篇一律的机器模板。

## 阶段 5：完整性验证

完成后检查：

1. 开头到结尾的重要内容是否都有对应章节。
2. 大纲中的所有章节是否已生成，顺序是否一致。
3. 用户选择的详细程度和附加模块是否落实。
4. 原文有时间戳时，首尾范围是否覆盖完整；没有则跳过此项。
5. 是否存在突然截断、空章节、重复章节或未经原文支持的内容。
6. 若写入文件，检查文件行数、大小和二级标题列表。

最后向用户报告输出位置（如有）、章节数、处理范围和验证结果。

## 核心原则

1. 先预读再提问，问题必须贴合材料。
2. 模型负责判断推荐项，用户负责最终选择。
3. 长内容先确认大纲，再逐章生成。
4. 内容质量优先于附加模块数量。
5. 保留关键细节和原话，但删除无价值口语噪声。
6. 时间戳、表格、摘要等都是按需使用，不是硬性装饰。
7. 不编造原文没有的信息，不因追求结构而改变原意。
