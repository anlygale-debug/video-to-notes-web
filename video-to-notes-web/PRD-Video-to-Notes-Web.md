# PRD: Video-to-Notes Web 应用

---

## 1. Summary

把现有 `video-to-notes` 命令行工作流（视频链接 → 下载 → 转录 → 结构化笔记）封装为一个本地 Web 应用。用户浏览器打开页面，粘贴链接或输入搜索词，等待处理，拿到可预览、可下载的 Markdown 笔记。先做本地部署，保留公网部署空间。

## 3. Background

### 当前状态

已经有一个完整的命令行 skill（`video-to-notes`），能够：

1. 搜索小红书视频或接收直接链接
2. 通过 xsec_token 获取视频 CDN 直链
3. 下载视频 → ffmpeg 提取音频
4. Groq Whisper 逐字转录
5. 结构化生成 Markdown 笔记

**痛点**：每次都要在终端里交互，需要打字命令，体验不够直观。想看笔记内容还得打开文件。

### 为什么现在做

- 核心管线已跑通（~30 秒全流程），稳定性验证过
- 所有依赖已在 `~/.agent-reach-venv` 中
- Groq Key 已配置，代理已配置
- Web 化后使用门槛降到零：粘贴链接 → 点按钮 → 看结果

### 技术可行性

- Python 后端用 FastAPI（已有 venv，再加一个 pip 包）
- 前端用纯 HTML/CSS/JS，设计参考 frontend-design skill
- 所有核心逻辑已存在，主要是"套壳"工作
- 本地服务，无用户系统、无数据库、无认证

---

## 4. Objective

### 目标

**把「视频 → 笔记」变成一个零门槛的本地 Web 工具。** 打开浏览器即可用，不需要终端、不需要记命令。

### 为什么重要

- 降低使用阻力：终端命令行 → 浏览器按钮
- 可视化预览：生成后立刻能看到笔记效果
- 复用性：别人也能用（本地局域网访问）

### 不做的事

- 不建用户系统、不说话注册登录
- 不做公网部署（第一版，预留接口即可）
- 不做飞书自动发布（web 应用替代了这个需求）

### OKR

| Key Result | 衡量方式 |
|------------|---------|
| 用户能在 3 次点击内拿到笔记 | 粘贴链接 → 点开始 → 下载/预览 |
| 处理速度不低于命令行版本 | 小红书 ~30s, B站 ~20s |
| 零配置启动 | `./start.sh` 一键启动 |
| 搜索能力对齐现有 skill | 搜索关键词 → 选视频 → 笔记 |

## 5. Market Segment(s)

### 目标用户画像

**知识工作者 / 内容消费者**，典型场景：

- 刷到小红书/B站/YouTube 视频，想存笔记但不想手写
- 看深度内容（教程、分析、行业解读），需要结构化总结
- 习惯用浏览器胜过终端
- 可能不会/不想用命令行

### 用户问题

| 问题 | 当前状态 |
|------|---------|
| 看了视频记不住 | 需要手写笔记 |
| 想做笔记但懒 | 工具门槛太高 |
| 视频太多看不过来 | 需要快速提取关键内容 |
| 笔记散落各平台 | 需要一个统一的笔记出口 |

### 约束

- 运行在本地电脑，不能有外部依赖（除了 API）
- 需要代理才能访问 Groq（中国大陆）
- 只支持中文视频（Groq language=zh）

## 6. Value Proposition

### 用户获得什么

- **省时间**：14 分钟视频 → 30 秒处理 → 结构化笔记
- **零摩擦**：浏览器粘贴链接，不用记命令
- **可编辑**：输出 Markdown，用什么编辑器都能打开
- **有预览**：生成后在页面里直接看笔记效果

### 避免哪些痛点

- 避免学命令行
- 避免手动找视频、下载、转录的繁琐
- 避免转录后还要自己整理（AI 帮你结构化）

### 与现有方案对比

| | 命令行 skill | Web 应用 |
|------|------------|---------|
| 使用方式 | 终端打字 | 浏览器点击 |
| 上手门槛 | 需要会 CLI | 零门槛 |
| 结果预览 | 打开 md 文件 | 页面内直接看 |
| 分享给他人 | 不可能 | 局域网访问 |
| 搜索视频 | Claude 帮忙 | 自己搜、自己选 |

### 7.4 技术方案

**后端：Python FastAPI**

```
routes:
  POST /api/search      → 搜索视频（跨平台）
  POST /api/process     → 下载 + 转录 + 生成笔记（Server-Sent Events 推送进度）
  GET  /api/notes/{id}  → 获取已完成的笔记内容
  GET  /api/download/{id} → 下载 md 文件
```

**核心模块（复用现有代码）：**

| 模块 | 来源 | 职责 |
|------|------|------|
| `xhs_resolver` | `~/.agent-reach-venv` xhs cli | 小红书短链解析、搜索、CDN 直链 |
| `downloader` | yt-dlp + curl + ffmpeg | 视频下载 + 音频提取 |
| `transcriber` | Groq API（curl） | Whisper 转录 |
| `note_generator` | 新写 | 结构化笔记生成（LLM 整理） |
| `feishu_publish.py` | 已有（暂不用） | 保留备用 |

**前端：纯 HTML/CSS/JS（单文件）**

- 不引入框架（零构建、零依赖）
- SSE（Server-Sent Events）接收实时进度
- Markdown 渲染用 `marked.js` CDN 加载
- 设计风格参考 frontend-design skill

**启动方式：**

```bash
# start.sh
source ~/.agent-reach-venv/bin/activate
pip install fastapi uvicorn sse-starlette  # 一次性
uvicorn app:app --host 0.0.0.0 --port 3000
```

### 7.5 文件结构

```

├── static/
```

所有临时文件放 `/tmp/vtn-<uuid>/`，处理完自动清理。

### 7.6 假设与风险

| 假设 | 如果不对怎么办 |
|------|---------------|
| Groq API 持续可用 | 预留接口，支持替换其他 Whisper 服务 |
| 代理 127.0.0.1:7890 一直运行 | 启动时检测代理，无代理时提示 |
| 用户已登录小红书 | 提示用 `xhs login --qrcode` |
| 视频时长 <20 分钟 | 更长视频分段转录 |
| 只在本地使用 | 不做鉴权，不暴露公网端口 |
