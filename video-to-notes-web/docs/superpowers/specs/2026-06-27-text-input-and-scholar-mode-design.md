# 文本输入 + 详解模式设计

## 目标

新增两种能力，不改动现有功能：
1. **文本直接生成笔记**：跳过搜索/下载/转录，直接对粘贴的文本生成笔记
2. **详解模式（scholar）**：第三种笔记样式，逐段详解式叙述，适合产品经理等知识理论课，阅读即可替代看视频

## 功能规格

### 1. 文本输入入口

前端新增输入方式切换，两种模式互不干扰：

- **链接模式**（默认）：保持现有 UI 不变——URL 输入框 + 平台选择 + 搜索按钮
- **文本模式**（新增）：大文本框（textarea）替代 URL 输入框 + 搜索按钮区域

切换方式：输入区域顶部两个 tab 按钮，`链接` | `文本`，视觉上轻量切换。

文本模式下：
- 显示标题输入框（必填，纯文本模式没有自动获取标题的来源）
- 隐藏平台选择下拉框（不涉及平台）
- 隐藏搜索按钮（不需要搜索）
- 模式选择（标准/详细/详解）照常显示
- "粘贴转录文本"按钮改为"生成笔记"
- 处理完成后，下载区域：正常显示 Markdown 下载和 PDF 导出，不显示音频下载、不显示转录下载、不显示合并下载/完整包下载（没有音频和转录来源）

### 2. 详解模式（scholar）

新增第三种笔记生成样式，与 standard / detailed 并列。

**触发条件**：用户在模式选择中点击"详解"，且通过 API `mode=scholar` 传入。

**Prompt 结构**：

输出格式要求：
```
# {标题} — 详解笔记

> 来源：文本输入 | 生成时间：{时间}

---

## 本节概览
[2-3句话：讲了什么、解决什么问题、适合谁看]

## 逐节详解
（按内容逻辑顺序，每个独立话题一节，不跳过任何内容）
### 一、{话题/概念名称}
[老师怎么引入的、核心定义、为什么重要、老师举的例子、关键细节和注意事项]
### 二、{话题/概念名称}
...

## 关键术语表
| 术语 | 解释 | 关键表述 |
|------|------|----------|
| ... | ... | ... |

## 一句话总结
```

核心规则：
- 输出中文
- 段落式叙述（不是要点列表），保留上下文和逻辑链
- 保留关键原话/表述，用 > 引用
- 每个话题至少写一段详细解释
- 不跳过任何内容章节
- 适合不看原视频直接阅读学习
- 适合放入 Obsidian 阅读和高亮
- 输出纯 markdown，不额外文字

**最大 token**：32000（内容篇幅比 standard 长）

### 3. 长文本自适应分块（scholar 专属）

scholar 模式对完整性要求最高，文本长度差异大（几百字到几万字），采用自适应策略：

**判断逻辑**：
- 转录文本 ≤ 8000 字 → **单次 scholar**，一次 LLM 调用生成完整笔记
- 转录文本 > 8000 字 → **分块 + 汇总**，两阶段处理

**分块流程**（长文本时自动触发）：
1. **切块**：按 ~6000 字一块，300 字重叠，切为 N 块
2. **并行处理**：每块用 scholar 风格 prompt 生成该块的"逐节详解"段落，最多 3 线程并发
3. **汇总调用**：N 块全部完成后，将所有块的"逐节详解"内容合并，做一次汇总 LLM 调用，生成：
   - `# 标题`
   - `## 本节概览`（基于全部内容的全局概括）
   - `## 关键术语表`（统一去重）
   - `## 一句话总结`
4. **拼接输出**：汇总头部 + 各块逐节详解（按顺序）

**LLM 调用次数**：N 块并行 + 1 次汇总。用户无感知，自动判断不走手动选择。

### 4. 链接模式下也可用详解

用户粘贴链接时也能选"详解"模式：下载 → 转录 → scholar prompt 生成。链接模式下三种模式均可选。

## 技术实现

### app.py 改动

1. `/api/process` 新增可选参数：
   - `text: str` — 直接文本内容，有值时跳过 resolve/download/transcribe，直接生成
   - `title: str` — 文本模式下必填，链接模式下可选（覆盖 meta title）

2. `step_generate()` 新增 `mode="scholar"` 分支，调用 `_generate_scholar()`

3. 新增 `_generate_scholar(task_id, transcript, meta)` 函数：
   - 内部判断文本长度，≤8000 字单次调用，>8000 字自动分块+汇总
   - 分块逻辑复用 detailed 的 chunk + ThreadPoolExecutor 模式
   - 汇总阶段单独一次 LLM 调用生成概览、术语表、总结

4. SSE 流程调整：
   - 文本模式：跳过 resolve/download/transcribe 步骤，直接进入 generate
   - 进度事件照发，但 download/transcribe 步骤发 skipped 事件
   - 链接模式：流程完全不变

### 前端改动（index.html）

所有改动在原 `index.html` 上进行，不动 `index-v2.html` 和 `index-v1-backup.html`。

1. **CSS 新增**：tab 切换样式、textarea 样式、三按钮样式（保持现有配色体系）
2. **HTML 新增**：
   - 输入区顶部 tab 切换按钮组
   - 文本模式下的 textarea 和标题 input
3. **JS 新增**：
   - tab 切换逻辑，显示/隐藏对应区域
   - 文本模式下调用 `/api/process` 时传 `text` 和 `title` 而非 `url` 和 `platform`
   - 模式选择按钮逻辑从 2 个扩展到 3 个
   - 文本模式结果区不渲染音频/转录下载按钮

### 不变项

- Standard 和 detailed 模式的 prompt、流程、触发条件完全不变
- 搜索功能不变
- PDF 导出、各下载端点不变
- 链接处理流程完全不变
- 不新增 Python 依赖

## 错误处理

- 文本为空 → 前端 disabled 按钮 + toast 提示
- 标题为空 → 前端 disabled 按钮 + toast 提示
- LLM 调用失败 → 降级为基础笔记（同现有逻辑）
- 文本超长（>50000 字符）→ 前端截断提示，后端不做限制

## UI 风格约束

- 复用现有 CSS 变量（--bg, --surface, --border, --text, --heading, --accent 等）
- tab 按钮风格与现有一致：border + border-radius: var(--radius)，选中态用 accent 色
- textarea 与 input 同风格：相同 border、padding、border-radius、focus 态
- 模式选择第三个按钮样式与现有两个按钮一致
- 不做任何全局样式改动，只追加
