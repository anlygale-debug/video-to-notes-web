## 二、新增代码

### BaseResolver 抽象基类

```python
class BaseResolver:
    platform_id: str = ""
    def search(self, query, task) -> list[dict]: ...
    def resolve(self, url, task, **kwargs) -> dict: ...
    def download(self, meta, output_path, task) -> bool: ...
```

### YtDlpResolver（主力解析器）

- `search()` — `yt-dlp --flat-playlist --dump-json "ytsearch8:{query}"`
- `resolve()` — `yt-dlp --dump-json` → `_map_meta()` 统一字段映射
- `download()` — `yt-dlp -x --audio-format mp3`
- `_cookie_flags()` — B站/抖音先带 Chrome Cookie 再裸连
- `_map_meta()` — yt-dlp 原始字段 → 标准 Meta 字典

### XhsResolver（小红书专用）

将原有 xhs 分支逻辑完整搬入，保留：
- 短链追踪（xhslink → 提取 note_id + xsec_token）
- 新旧 xhs-cli 响应格式兼容（`data.items[0].note_card` / `data.*` flat）
- CDN 直链提取（`video.media.stream` → `masterUrl`）
- curl + ffmpeg 下载

## 四、Bug 修复

### Bug #1: 环境变量命名冲突导致 LLM 调用失败

**严重程度**: 🔴 高

**现象**: 在 Claude Code 环境中启动 app 时，笔记生成步骤走兜底函数（`_basic_notes`），只输出原始转录文本，缺少 AI 结构化内容。但通过 `start.sh` 或 macOS `.app` 启动时正常。

**根因**: `_read_api_config()` 使用 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` 环境变量，与 Claude Code 自身的环境变量**命名完全相同**。Claude Code 设的值（`https://api.deepseek.com/anthropic`、`DeepSeek-V4-pro[1m]`）不符合 app 的 OpenAI 兼容 API 请求格式，`_call_llm()` 失败 → 走兜底函数。

**修复**: 环境变量名改为项目专属：
```
ANTHROPIC_AUTH_TOKEN  → VTN_API_KEY
ANTHROPIC_BASE_URL    → VTN_API_BASE
ANTHROPIC_MODEL       → VTN_MODEL
```

**影响范围**: 仅 `_read_api_config()`（第 497 行）。settings.json 配置路径不受影响。如果之前有人手动设过旧的 `ANTHROPIC_*` 环境变量来覆盖配置，需要改用新名称。

**Commit**: `17d8a1c`

---

### Bug #2: 兜底函数文案过时

**现象**: `_basic_notes()` 输出的笔记标注「转录：Groq Whisper large-v3」，实际已改用本地 Whisper tiny。

**修复**: 文案改为「转录：本地 Whisper tiny」。

---

### Bug #3: yt-dlp 简介字段显示 "-"

**现象**: B站视频的 `description` 字段显示 `-` 占位符。

**修复**: `_map_meta()` 中对空值和 `"-"` 统一置为空字符串。
