# ADR 0001：使用 SQLite 作为本地事实源

> 日期：2026-07-27
> 状态：已采纳用于技术规格；尚未实现

## 背景

当前任务保存在 Python 进程内，解析与笔记历史分别保存在浏览器 localStorage。锁定的 UI 合同要求同浏览器任务恢复、两套历史双向关联、逐字稿副本独立所有、版本恢复和明确的非级联永久删除。

## 决策

使用 `data/vtn.sqlite3` 作为任务、解析记录、笔记、版本、关联和工作流事件的本地唯一事实源。浏览器 localStorage 只保存 `device_id`、事件游标和一次性迁移标记，不保存业务正文。

## 备选方案

### 继续使用内存 + localStorage

实现成本最低，但服务重启会丢任务，后端下载无法可靠定位历史资产，两套历史难以保证关联和删除边界。

### 多个 JSON 文件

保持可读，但跨记录事务、并发写入、分页、版本和关联完整性需要自行实现，复杂度会扩散到所有调用者。

### SQLite

无需额外服务或账号，支持事务、外键、分页和本地备份，能把持久化复杂度集中在一个 repository 模块。

## 结果

- 引入 schema 和迁移管理。
- 所有写入通过 SQLiteRepository。
- 外部调用不能占用数据库事务。
- localStorage 旧数据需要一次性导入。
- 将来公开部署时可以在 repository seam 后增加其他 adapter，而不改变 workflow interface。
