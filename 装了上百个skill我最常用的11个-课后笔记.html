核心理念

Skill装多了真的非常容易乱。

姜学长装了上百个 Skill，但日常真正高频使用的只有 11 个。他按场景分为三条线：提效率 做产品 做内容

一、效率工具线 5个

1. Agent Reach ✅ 已安装
以前搜资料需要一个平台一个平台去切换，现在只需要一句话说清楚你要什么。
一句话跨平台搜索：YouTube、小红书、Twitter、公众号都能通查 · 直接提取字幕，不花 API 费用
2. NotebookLM Skill 未安装
把采集来的资料批量导入，让它去做归纳分析，不用打开浏览器，命令行里面直接搞定。
终端里操控 NotebookLM · 批量资料导入 → 自动归纳分析
3. BB Browser 未安装
让 AI 直接接管你的 Chrome——打开网页、点按钮、填表单、截图、爬数据，跟你自己坐在电脑前面操作没有任何区别。
AI 操控浏览器执行重复流程 · 每天重复的操作丢给它就行
4. Skill Creator 未安装
Cloud 的官方出品，写 Skill 的 Skill。把你每天重复的工作流程用一句话描述出来，它能帮你封装成可以反复调用的 Skill。
把重复工作流程封装成 Skill · "教会 Claude 按照你的方式工作" · 长期价值非常高
5. Find Skills ✅ 已安装
Skill 的搜索引擎。不知道该用哪个 Skill 的时候，把需求告诉它，它根据上下文帮你找到最合适的。
不用自己一个一个翻 Skill 列表

二、产品开发线 5个

6. G-Stack 未安装
硅谷创业圈出来的开源技能库。里面的 Office Hours 是我用得最多的——说任何事之前，先被 AI 连问六个问题，把目标和边界条件逼出来。
硅谷创业圈开源技能库 · Office Hours：做事之前先被AI追问6个问题，逼出目标和边界 · "跳过这一步，做出来的东西返工率高很多"
7. Cyberpowers 未安装
给 Claude Code 装的一套工程师工作习惯。拆任务、写测试、代码审查这些流程默认就会走，不用你每次都提醒。
自动走工程流程：拆任务 → 写测试 → 代码审查 · 把 AI 编程从「能跑就行」推到「可以去交付」
8. Frontend Design ✅ 已安装
你不懂设计没关系，排版、配色、交付细节它自己去判断。从零生成页面。
零基础生成前端页面
9. UI UX Pro Max 未安装
在现有的基础上去做优化。
已有页面的 UI/UX 优化 · 和 Frontend Design 互补：一个从零生成，一个在现有基础上优化
10. Playwright MCP 未安装
产品做完以后，让它模拟用户操作去跑一遍。哪里点不动、哪里报错了全部暴露出来，你不用自己手动一个一个点。
自动化测试 · 模拟用户操作 → 发现问题 → 自动暴露

三、自媒体线 1个

11. Keymanizer-ZH 未安装
规范大佬的出品。AI 写的东西通顺归通顺，但读起来不像人话。这个 Skill 专门处理这个问题，过一遍之后自然度明显不一样。做内容的基本上都用得上。
让 AI 文字读起来更像人话 · 做内容的几乎必装 · 姜学长几乎每天都在用

六、个人思考

  1. Skill 不是越多越好 —— 姜学长装了上百个，真正用的只有 11 个。关键是按场景找到自己的核心工作流，不是追求数量
  2. 三条线思维值得借鉴 —— 提效率（输入/处理）、做产品（输出/交付）、做内容（传播），覆盖了一个 AI 创作者/开发者的完整闭环
  3. Skill Creator 是最被低估的 —— 「写 Skill 的 Skill」意味着能力可复制、可封装，长期来看这是杠杆率最高的一个
  4. G-Stack 的 Office Hours —— 「做之前先被追问 6 个问题」这个方法论单独拎出来就是一种工作习惯升级
  5. 我们本地的缺口：11 个里装了 3 个，还有 8 个可以按需安装。可以先从效率线补起
